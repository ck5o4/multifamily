## Fixed (each REPRODUCED, each with a regression test)

**F1 — PDF ingestion was dead on every fresh container.** `tools/parsers.py:75`
imports `fitz` (PyMuPDF) for the PDF path README and CLAUDE.md both advertise,
while `requirements.txt` declared only `openpyxl`. `parse_rent_roll()` on the
real `deal-intake/baker-trails/Baker_Trails_OM_June.pdf` raised
`ModuleNotFoundError`; all four deal-intake PDFs affected. Declared
`PyMuPDF==1.28.2` — pinned, because ≥1.28 deprecates the `fitz` alias the parser
uses. The OM then parsed 177 rows. `.claude/hooks/session-start.sh` installs from
`requirements.txt`, so this propagates to every future scheduled run. The new
test walks the real import graph, so the next undeclared dependency fails in the
suite rather than on a live deal package.

**F2 — `recalc.py` reported LibreOffice as available when it is unusable.** This
container carries `libreoffice-core` without `libreoffice-calc` (no `scfilt`
filter), so `find_soffice()` returned `/usr/bin/soffice` and every conversion
died with the opaque `source file could not be loaded` — *after* a full intake
run had written its inputs. Reproduced on a trivial two-cell workbook, proving
the filter and not the model workbooks. `INSTALL_HINT` also told a Linux cloud
user to run `brew install --cask libreoffice`. Now detects the missing filter up
front with a platform-correct message; detection is fail-open so an unrecognised
layout never blocks a working install.

**F3 — [CRITICAL] a plural "Totals" row was parsed as a unit type.**
`tools/parsers.py:25` — `TOTAL_ROW_RE` ended in `\b` after a bare `total`, so
`Total` matched and `Totals` / `TOTALS` / `Subtotals` / `Averages` did not. The
row survived because its summed SF and summed rent sit inside `SF_MAX`/`RENT_MAX`,
so it read as one large unit. On a 4-unit fixture through the real intake path:

| | correct | parsed |
|---|---|---|
| units written | 4 | **5** (`Totals`, 3,000 SF, $3,450) |
| NOI yr 1 | $15,422 | **$46,794** |
| levered IRR | −1.23% | **+22.27%** |

A hard PASS presents as "22% — your ideal". The only note printed was the generic
"no parseable bed/bath". Fixed; the real baker-trails roll is unchanged.

**F4 — [CRITICAL] the rent column was chosen by position, not preference.**
`tools/parsers.py:_find_header` scanned columns left-to-right and took the first
rent-ish header, making the `_HDR_RENT` preference tuple dead code — and that
tuple listed **`market rent` first**, so honouring it as written would have been
worse, not better. Underwriting runs on in-place rent; market rent is the
seller's aspiration. Reproduced on the real baker-trails OM roll with the two
columns swapped into Yardi/RealPage order:

| | Current-Rent first | Market-Rent first |
|---|---|---|
| 2BR rent | $725 | **$838** |
| NOI yr 1 @ $750K | $42,542 | **$52,795 (+24.1%)** |
| loan at 1.30 DSCR | $394,706 | **$489,831 (+$95,125)** |
| 13% clearing price | $465,119 | **$569,231 (+$104,111)** |

Worst of all, the four `$0` vacant rows picked up a market rent, so **both the
zero-rent note and the `IMPLIED PHYSICAL VACANCY 4/12 = 33.3%` warning
disappeared** — the warning added for this exact deal on 2026-08-24. Fixed:
preference reordered (actual/current/in-place first, market/asking last), the
selection now honours it, and the losing column is reported. Verified the swapped
roll now yields $725/$925 with both warnings intact, identical to the correct
column order.

**F5 — `parceltax.py` bypassed the `commercial_share` guard.** The 2026-09-07 fix
landed only in `latax.estimate_tax`; `parceltax.py` imported the ratio constants
and did its own arithmetic. `--commercial-share 30` on a $1.5M Ascension building
printed **$276,000/yr**, 16× the $17,250 truth; `-0.5` printed **$12,938**, 25%
*below* the residential floor, unwarned. This is the tool run immediately before
an offer, against one of CLAUDE.md's hard pre-offer gates. Guard extracted to
`latax.validate_commercial_share` and called from both. Valid inputs unchanged
(0.3 → $19,838; default → $17,250).

**F6 — `monte_carlo()` discarded the deal's own exit cap.** `tools/pymodel.py`
overwrote `exit_cap` with `going_in + cap_delta` on every draw and never read
`inputs["exit_cap"]`, so a deal underwritten at any other cap had its MC — and
the house-rule beats-index scored off it — evaluated at a cap the underwriting
rejected, with no diagnostic. On `mlk-2119` (workbook 7.50% vs 5.03% going-in)
**100% of drawn caps fell below the deal's own**, putting MC P50 at −1.93%
against a deterministic −9.79% — the MC centre **7.9 points above** the
underwriting. Fixed by centering the draws on the underwritten cap and keeping
the fitted spread, exactly as rent and expense growth are already treated; the
centre is now reported in `growth_note`. P50 −1.93% → −12.67%.
**No live deal moves** — eden, treme and baker all carry `exit_cap == going-in +
50bps` exactly, so the recentering is a no-op for them (verified).

**F7 — `portfolio_sim` mis-ruled the capital-gap test in both directions.**
`tools/portfolio_sim.py` updated `running_bal` once per year, *after* both the
acquisition and the distribution loops:

- **Two deals in one year** — the second was tested against cash the first had
  already spent. Baker ($138,472) + Gonzales ($179,329) = $317,802 against
  $300,000 raised **no flag at all** and printed a −$17,802 year-0 balance.
- **Buying in the year another deal sells** — the test ran before the sale was
  credited, inventing a **$98,929 capital call** against $175,953 of proceeds
  received that same year; `running_bal += shortfall` then overstated the closing
  balance by exactly that phantom ($175,953 vs a true $77,025).

Fixed by crediting distributions and savings before the acquisition loop and
deducting each purchase from `running_bal` as it is made. A deal bought in year N
pays nothing in year N, so there is no circularity. Case A now flags the $17,802
gap and closes at $0; case B raises no gap and closes at $77,025. CLAUDE.md makes
equity the binding constraint and "sell one, roll into the next" the documented
strategy, so case B is the ordinary path, not an edge case.
