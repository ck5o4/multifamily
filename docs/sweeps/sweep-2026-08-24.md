## Findings fixed (with reproduction)

### F0 — Scheduled runs started with no openpyxl · REPRODUCED · CRITICAL (infra)

`test_pymodel.py` / `test_mc.py` / every workbook read died at import. Added

### F1 — Price solver returned a stale, too-low price · REPRODUCED · CRITICAL
`tools/solve.py:92` and `tools/pymodel.py:886`. The bisection break tested the
last midpoint probe (`irr_mid`) instead of the best clearing price it would
return, and `solve.py` had no `best is not None` guard at all (the 2026-08-09
fix was never ported there — and `solve.py` is what `intake.py --solve-price`
calls). Effects, IRR oracle = pymodel/workbook:

| deal | target | reported | truth | error |
|---|---|---|---|---|
| eden-church-mhp | 13% | $1,423,000 | $1,559,000 | **−$136,000** |
| covington-2nd | 16% | "unreachable" | $841,000 | false negative |
| hwy42-mhp | 16% | $2,269,000 | $2,298,000 | −$30,000 |

Also the result was **rounded** to the nearest $1,000, which rounds *up* past the
clearing boundary so the reported price no longer clears its own label
(treme 16% → $664,000 @ 15.997%). Fixed both: break on `best["irr"]`, floor
instead of round. Every ladder rung now clears its target (regression test
covers all 6 live deals × 3 targets).
**Decision impact:** eden's `--solve-price` was a $136K under-offer on the top
deal; covington 16% was wrongly "unreachable".

### F2 — MC drew looser growth than the deal underwrites · REPRODUCED · CRITICAL
`tools/pymodel.py` (~1300). The 2026-08-09 sweep recentered MC *vacancy* on each
deal's underwriting but left rent growth on the fitted FRED marginal (P50 3.215%
vs a 2.0% underwrite) and expense growth (2.147% vs 2.5%). Both errors point the
same way, so **MC P50 exceeded the deterministic IRR on all seven deals** and
every quoted P(≥13%) / beats-index inherited the optimism (eden P50 12.18% vs det
9.87%; treme 8.12% vs 6.57%). Fixed by recentering both on the deal's own
underwriting, keeping the fitted spread, exactly as vacancy is — with a
`growth_note` surfaced in the memo and CLI. Post-fix eden P50 6.0%, treme 0.4%.
**Decision impact:** combined with F3, this is what moves treme below the gate.

### F4 — Source-file discovery silently took the wrong file · REPRODUCED · HIGH
`tools/intake.py:39`. `discover()` took the alphabetically-first match per slot
and dropped the rest, against the README's "nothing is silently dropped".
baker-trails → `..._ESTIMATED.csv` (GPR $118,800) over the seller's
`..._OM_2026-08-13.csv` (real 8×2BR/4×3BR mix); hwy42 → `P&L 2025.xlsx` over

### F5 — Rent roll's own vacancy discarded · REPRODUCED · HIGH
`tools/parsers.py:349`. Vacant units' rents are imputed from the type median so
they enter gross potential income, but the roll's implied physical vacancy was
never surfaced against the (7% template default) vacancy input. On baker's OM
roll that is 4/12 = 33.3% vs 7% — roughly $30K/yr of NOI on a $750K asset. Fixed:
parser emits `IMPLIED PHYSICAL VACANCY n/N = x%`, and intake prints a warning
when it materially exceeds the vacancy input. (Made reachable by F4's fix.)

### F6 — Part-year T-12 read as annual · REPRODUCED · HIGH
`tools/parsers.py`. Neither T-12 path counted populated period columns, so
hwy42's `P&L YTD 2026.xlsx` (Jan–Jun only) produced half-size "annual" expenses
(insurance $12,750 vs true $25,500) with `basis` still reading "under total
header". Fixed: count populated periods; if most lines agree on <12, raise a
`PART-YEAR STATEMENT` note and stamp every line's basis. Silent on both full-year
controls. (Made reachable by F4's fix.)

### F7 — Flood lookup degraded optimistically and killed runs · REPRODUCED · CRITICAL
`tools/flood.py` (8b7ce5e, the commit under audit). Three defects: (a) `fetch_json`
raised `SystemExit` (a `BaseException`), so every `except Exception` guard in
intake/icmemo was dead code and any service failure killed the whole run —
discarding a completed Monte Carlo in icmemo; (b) an empty/`features`-less
response and the FEMA domain values `AREA NOT INCLUDED` / `OPEN WATER` (plus any
unrecognised zone) reported "minimal flood hazard"; (c) unmapped parcels returned
`sfha=False`, so icmemo's `if sfha` gate dropped the flood line and asserted
"SFHA: No". Fixed: catchable `FloodLookupError`; unknown/unstudied zones →
UNDETERMINED with `sfha=None`; consumers treat `None` as an explicit UNKNOWN gate,
never as clear. Plain X still minimal, AE still SFHA.
**Decision impact:** prevents a false "no flood policy" on any NOLA-box deal
(a missed lender-required policy at $1,000/unit/yr moves treme's 13% price ~$83K).

### F8 — RentCast cache silently unmatched on live deals · REPRODUCED · HIGH
`tools/pymodel.py` (~1180). The 2026-08-09 "all tokens must match" hardening
produced false negatives: cache files are named for the street address, deal
slugs for the neighbourhood, so `treme-gov-nicholls` shared no token with
`1429-governor-nicholls-st…` and its paid cache was ignored — MC then ran with no
rent-level uncertainty and printed nothing. Fixed: explicit `rentcast` filename
hint in `deals.json` (added for treme/baker/cannon/covington), slug-token match
as fallback, and the absence is now always loud (`rent_level_note`). eden's own
cache still matches; cross-property match still rejected.

### F9 — `_irr` returned a number with no sign change · REPRODUCED · HIGH
`tools/pymodel.py:72`. All-zero flows returned the bisection midpoint (450.05%);
`[0,…,0,X]` returned the Newton clamp (5000%). Reachable in one step from the
documented `lp_pct=1.0` (investor funds all equity → `gp_capital=0`), which
printed "GP IRR: 450.05%". Fixed: return `None` unless the flows change sign.
GP IRR now `None` when the LP funds all equity.

### F13 — "Hot market" upside scenario priced as downside · REPRODUCED · MEDIUM
